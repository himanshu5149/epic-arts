# Epic Arts
### Ancient stories. A new home.

A complete, responsive, digital-only storefront for contemporary Mithila- and heritage-inspired art, expanded with a working generative studio, a guarded Art Advisor, and 100,808 public editions. The preview has **free demo checkout and real downloads**. No real payment is collected without a configured payment provider.

## Included

- An editorial home page, twenty-eight generative families, a research-led trend edit, and **100,808 public editions**: 100,800 reproducible designs (28 families × 3,600 editions) plus the original eight products (six single artworks and two sets).
- Indexed FTS search, collection/family/color/budget filters, seven sorting choices, 24-item gallery pages, persistent saved pieces, and a persistent slide-out bag. Digital licenses are intentionally one per product; there are no meaningless quantity controls or shipping forms.
- Routed product pages with four gallery views, zoom, context about each tradition, file details, sample reviews, review sorting, and order-gated review submission.
- A minimal checkout, server-authoritative totals, working `EPIC10` promotion, idempotent order creation, and clear demo/live states.
- Real protected ZIP downloads, a browser-linked library, and hashed private-access links. Files are never served from the public asset directory. Purchase status and product ownership are checked on every download.
- SQLite WAL persistence for indexed catalog, orders, immutable item/recipe snapshots, sessions, access-token hashes, studio jobs/private products, newsletter consent, and submitted reviews.
- A no-key procedural design studio: family, palette, detail, composition seed, keyword-based mood suggestions and automatic “surprise me” generation. Generated editions can actually be collected and downloaded.
- A budget-safe Art Advisor: four permissioned specialist roles, coherent gallery-wall proposals, source-linked guide answers, dated research, a real collection-to-bag flow, and matching Studio handoff. No-key mode is rules + indexed retrieval; an optional consent-gated language model is bounded and server-side.
- Durable private advisor runs, retry-safe request keys, per-role tools, hash-linked action verification, quotas, recovery, retention and a capability-free downloadable JSON brief.
- Optional server-side OpenAI image-provider integration with moderation, explicit provenance and bounded job allowances; off without operator credentials.
- Transparent trend sources and dates, honest zero-review states for new designs, and paid-only popularity/rating sorts. See `MARKET-RESEARCH.md`.
- An interactive **wall planner** at `/wall`: six original curated edits of existing editions, an illustrative frame mockup with wall tones, sizing, spacing and layout controls, an optional in-session photo of your own wall (never stored or uploaded), on-device plan persistence, share links that carry artwork choices only, a downloadable plan note, and explicit per-piece bag adds. Curated sets copy nothing: they combine Epic Arts’ own editions, labeled honestly as contemporary interpretations.
- **Celebration edits** at `/celebrations`: three original curated suites for weddings/new beginnings, housewarmings and anniversaries, built only from existing Epic Arts editions with honest provenance notes.
- An **inspiration shelf** at `/inspiration`: a read-only window into the Art Institute of Chicago’s public-domain collection via its open API (found through the cloned `public-apis/public-apis` directory — MIT, provenance in `vendor/public-apis/`). Museum works are clearly labeled references, never products, and the shelf degrades honestly if the museum is unreachable.
- **Gift orders**: optional “send as a gift” at checkout with recipient name and a short message; the order’s private gift link opens an animated sealed-envelope reveal before the downloads. Gift details ride the order only (never public), change detection covers them, and the reveal dismissal is remembered per-device.
- A **print-fit helper** on the printing guide and a **free one-page printer test sheet** (`/epic-arts-test-print.pdf`, regenerated by `scripts/generate-tools.mjs`) so visitors can check rulers, palette swatches and fine line work before printing. Size advice is arithmetic from real file dimensions — vector and upscaled originals are never given the same claims.
- Pluggable payment gateways, each strictly opt-in and server-side verified: **Stripe** (cards + Apple Pay/Google Pay/Link via automatic payment methods), **Razorpay** (UPI, QR, cards, netbanking & wallets — INR billing with a documented shop conversion rate, signed callback + signed webhooks), and **PayPal** (Orders API v2, server-to-server capture — no card data and no client SDK in the browser). Downloads unlock only after a confirmed, amount-matched capture; refund/dispute states revoke access. Optional Resend receipt email.
- An installable PWA, public offline browsing, an offline fallback, and explicit exclusion of orders, tokens, checkout, private advisor/Studio runs, APIs, and download files from the service-worker cache.
- Server-rendered HTML on public routes, unique page metadata, canonical links, Open Graph/Twitter cards, dynamic sitemap and robots.txt, Product/Breadcrumb/Organization/BlogPosting JSON-LD. **Fabricated demo reviews are not included in structured ratings.**
- Self-hosted fonts, optimized WebP images, reduced-motion support, keyboard dialogs, focus trapping, and accessibility checks.

## Run locally

Requires Node 20.19+ (Node 20.20 was used).

```bash
npm ci
npm run dev
```

Open the server on port 3000. It binds to `0.0.0.0`, supports the preview proxy, and uses one origin for both the app and API. Development defaults to free demo checkout. For a production-mode demo:

```bash
npm run build
NODE_ENV=production DEMO_CHECKOUT=true npm start
```

Production defaults to **checkout disabled** unless either free demo checkout is explicitly enabled or live Stripe credentials are fully configured. It never silently substitutes a fake paid transaction.

## Try the complete experience

1. Open the gallery and add a piece to your bag.
2. Continue to checkout. Use sample contact details; no credit card is needed for demo mode.
3. Optional: apply `EPIC10` for the displayed artwork-value discount.
4. Accept the personal-use terms and choose **Complete demo & get my art**.
5. Download the actual ZIP from your library. Save the private access link if you want to return on another device.

The demo charges $0.00. Catalog prices are sample USD artwork values. Reviews are explicitly labeled demo content.

## Make your own edition

1. Open **Create your own** (`/studio`). Choose a family, palette and detail level, or use **Let the studio surprise me**.
2. Optional: name the edition, match a mood using the clearly labeled keyword matcher, or choose a composition seed.
3. Select **Create my edition**. The built-in engine works without an API key.
4. Collect the result through the normal checkout and download its real ZIP from the library.

The engine is procedural drawing, not arbitrary text-to-image AI. Visitor-created editions are unlisted rather than automatically filling the public catalog. See `ARCHITECTURE.md` for the queue, access model and scaling boundaries.

## Let the Art Advisor help

1. Open **Art advisor** (`/advisor`), describe your space and set the total art budget, palette/direction and number of editions.
2. Find a real coordinated collection. The default Mithila/Indigo brief fits three editions into $60 with a $56 artwork value.
3. Read the provenance, file and license sources, inspect the checked actions, or choose another selection.
4. Click **Add collection to bag** to use normal checkout and real downloads. Nothing is added or ordered automatically.
5. Or open **Make a matching edition**: the Studio receives an approved family, palette and seed, but waits for your explicit Create click.

**No API key is needed.** The default is deterministic retrieval and validation, not four independent language models. Optional connected-model tool calling requires `AGENT_LLM_ENABLED=true`, a server-side `OPENAI_API_KEY`, and the visitor's opt-in. It is separate from Image AI and falls back safely when unavailable. No live model call was validated without credentials.

The named repository was actually cloned, audited and adapted. The two retained development skills were run offline; specialist/retrieval/permission/audit patterns are integrated in the app, not simply linked as demos. See **`AGENT-SYSTEM.md`** for source mapping, setup, APIs, permission boundaries, quotas and the honest single-instance scaling roadmap; see **`THIRD-PARTY-NOTICES.md`** for pinned source and Apache attribution.

## What the files contain

**Built-in generative editions** include nine files: a native SVG, 2400×3000 PNG, 2400×3000 JPG, three vector artwork PDFs (5×7, 8×10, A4), recipe JSON, a PDF print guide, and a personal-use license. PDFs preserve the full composition; 5×7 and A4 have a border. No upscaling is used to draw the vector originals.

**Original AI-assisted edit:** each single artwork ZIP includes:

- A 2400 × 3000 pixel JPG with 300 DPI metadata.
- 5×7 inch, 8×10 inch, and A4 PDFs (A4 includes a white border).
- A plain-text print guide and personal-use license.

The two sets contain the corresponding individual ZIPs. There is also a downloadable, designed PDF print guide at `/epic-arts-print-guide.pdf`.

**Original-edit source resolution:** these original artworks are AI-assisted and upscaled from a 1122 × 1402 pixel source. 300 DPI metadata does not create native detail. The site and guides recommend printing at **8×10 inches or smaller**. These are not authenticated antiques or hand-painted artisan originals, and the site does not claim an artisan-revenue partnership.

The original eight archives are committed under `private/downloads/`. Generated editions are exported on demand into a non-public regenerable cache, not shipped as a thousand large ZIPs. Optional image-AI editions include their raster original rather than an SVG; they are explicitly labeled resized/raster-based and recommended for small prints.

The original archives are ready to download without regenerating anything. To regenerate them from the included source art, install Python Pillow and ReportLab, then run:

```bash
pip install -r requirements-assets.txt
python scripts/prepare-assets.py
python scripts/print-guide.py
```

Do not run the asset scripts just to start the store. Font OFL licenses are in `assets/font-licenses/`.

## Live payments and deployment

Copy `.env.example` to `.env`, then set:

```dotenv
SITE_URL=https://your-real-domain.example
DEMO_CHECKOUT=false
STRIPE_SECRET_KEY=your-server-side-key
STRIPE_WEBHOOK_SECRET=your-webhook-signing-secret
DATA_DIR=/a/persistent/private/directory
```

Optional additional gateways (each appears at checkout only when fully configured):

```dotenv
# Razorpay — UPI, QR, cards, netbanking & wallets (INR)
RAZORPAY_KEY_ID=rzp_live_...
RAZORPAY_KEY_SECRET=...
RAZORPAY_WEBHOOK_SECRET=...      # enables signed payment.captured / payment.failed webhooks
USD_INR_RATE=84                  # documented fixed shop rate; paise are derived from USD cents
# PayPal — wallet & cards (USD), sandbox by default
PAYPAL_ENV=live
PAYPAL_CLIENT_ID=...
PAYPAL_CLIENT_SECRET=...
```

Gateway state machine, all providers: pending → paid only after server-side verification (Stripe signed webhook / verify-session, Razorpay HMAC-SHA256 signature or signed webhook, PayPal server-to-server capture with amount + order cross-check). Replay-safe and refresh-idempotent; a browser redirect is never accepted as proof of payment. Amounts are re-verified against the stored order; mismatches refuse to unlock. Refunds/disputes revoke downloads. Old orders migrate automatically (`gateway`, `gateway_ref` columns are additive).

Razorpay serves a self-hosted payment page (`/pay/razorpay/:orderId…`) that loads `checkout.js` under a CSP exception scoped to that single route; the gallery’s CSP everywhere else stays origin-only. PayPal never loads any PayPal script here — the buyer visits PayPal’s own site and returns to a server capture endpoint.

1. Verify that each gateway supports the operator’s legal business and country. Do not assume that a Nepal-based business can onboard to Stripe without a supported legal entity. A local gateway (e.g. eSewa/Khalti) would require a separate server-side integration; none is silently simulated here.
2. Start with Stripe test mode. Register `/api/stripe/webhook` for `checkout.session.completed`, `checkout.session.async_payment_succeeded`, `checkout.session.async_payment_failed`, `checkout.session.expired`, `charge.refunded`, and `charge.dispute.created`.
3. Configure taxes for your jurisdiction. If using Stripe Tax, enable `STRIPE_AUTOMATIC_TAX=true`, complete tax registrations and product tax categorization, and test before accepting payments. Otherwise the app does not invent or remit taxes.
4. Set `RESEND_API_KEY` and a verified `MAIL_FROM` if you want emailed receipts. Without these, download access opens in the browser and the UI does not claim that an email was sent. Test delivery and retry/monitor failures before launch.
5. Publish reviewed legal business details, operator support and recovery contact, retention/deletion process, and locally valid terms/privacy/license/returns policies. Included policies are transparent **samples**, not legal advice or a launch-ready legal identity.
6. Replace or explicitly retain demo artwork/reviews/prices. Do not represent illustrative reviews as verified testimonials. Use appropriate rights and provenance for any commercial replacement art.
7. Deploy on a persistent Node host or with the Dockerfile. Use HTTPS, a canonical `SITE_URL`, a persistent `/data` volume, and database/download backups. A static-only host cannot serve protected checkout/download APIs.
8. Run `npm run build` and the tests, submit `/sitemap.xml` to search consoles, and validate live canonical/OG URLs. SEO foundations do not guarantee search ranking.

### Docker

```bash
docker build -t epic-arts .
docker run -p 3000:3000 --env-file .env -e DATA_DIR=/data -e CACHE_DIR=/data/cache -v epic-data:/data epic-arts
```

The container runs as a non-root user. SQLite is designed for **one application instance** with a persistent volume. For multi-instance deployment, migrate the repository layer to a shared transactional database and private object storage, and add operational backup/restore, monitoring, customer recovery, and administrative tooling.

## Optional live Image AI

The built-in engine needs no credential. To enable the separate image-AI mode, configure server-side only:

```dotenv
AI_GENERATION_ENABLED=true
OPENAI_API_KEY=your-server-side-key
OPENAI_IMAGE_MODEL=gpt-image-1
AI_DAILY_LIMIT=5
```

Both flag and key are required. Confirm model access and set a hard provider-side spend cap. The application moderates prompts and limits reserved jobs, but a job quota is not a financial guarantee. Provider originals are stored under `DATA_DIR/source-images` and must be backed up. No live provider call was validated without credentials. Never put keys in a browser bundle.

## Security and privacy notes

- Every price and discount is recomputed on the server from allowlisted product IDs.
- Live downloads are only granted after confirmed payment. Stripe webhook signatures are verified over the raw body. Successful browser redirects are not accepted as proof of payment.
- Session cookies are random, HttpOnly, and secure on HTTPS. HTTPS uses partitioned SameSite=None cookies to support embedded previews; unsafe endpoints additionally require JSON and enforce Origin/Sec-Fetch-Site checks. Private access links also let an order work when a browser restricts third-party cookies.
- Private bearer-link tokens are random and stored only as hashes. Anyone with the complete link can access that order: treat it like a password. Keep token URLs out of analytics and logs. Private routes use no-store/no-referrer headers.
- APIs are rate limited, SQL uses prepared statements, and HTML renders user input through React escaping. Security headers and a production CSP are applied. Iframe blocking is intentionally absent for Arena previews; set an appropriate frame-ancestors allowlist for the final deployment.
- No card details are collected by the app. There is no email-only order lookup, advertising tracker, or analytics integration.
- The newsletter endpoint records explicit interest; this starter does not run a marketing campaign. A live sender must implement confirmation/unsubscribe and comply with local requirements.

Do not run bulk QA cleanup on a customer database. Developer skills remain manually invoked; they are not a public endpoint or a newly imposed CI policy.
